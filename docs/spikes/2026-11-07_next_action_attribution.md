# 다음 작업 귀속 검증 계획

작성 2026-11-07. 실제 모델 호출 전 계획 초안이다. 팀 승인·실험 실행·의미 판정은 미수행이다.

## 위험 가정

한 메모의 다른 행동에 속한 완료·장애·기한을 다음 행동에 잘못 붙이지 않으면서 후보 검토 부담을 줄일 수 있는가.

## 실험 전 확정할 항목

- 평가 단위는 고유 메모 한 건의 최초 모델 출력이다. 형식 복구 결과와 사용자 편집 결과를 따로 기록한다.
- docs/research/semantic_cases_draft.yaml의 의미 사례 4개를 팀이 검토하고, 별도로 아직 모델에 사용하지 않은 합성 메모 16개를 준비한다. 합계 20개와 기대값을 호출 전에 동결한다.
- 20개에는 행동 간 상태 귀속, 부정, 상대 기한, 불명확한 행동, 지시문 인용을 포함한다. 각 사례마다 허용 행동·허용 선택 필드·금지 추론을 사람이 작성한다.
- 제안 합격선은 의미상 정확한 최초 출력 18/20 이상, 다른 행동의 완료 귀속 0/20, 없는 장애·기한 생성 0/20이다. 중대한 오류 한 건이라도 있으면 불합격이다. 구조 통과율과 별도로 계산한다.
- 수정 후 저장한 결과를 최초 추출 성공으로 세지 않는다. 미판정은 성공이 아니며 의미 판정 20개 미완료는 결론 유보다.
- 사용성은 PROBLEM.md 5.2절에서 별도 관찰한다. 이 실험으로 재개 시간 단축을 주장하지 않는다.

## 실행·기록

실제 모델 호출은 명시적 요청과 사례 검토 후 수행한다. 메모 한 건 최초 + 형식 복구 1회 상한, 정책 실패와 null 행동은 자동 재호출하지 않는다. 실행 전 사례 버전·프롬프트·모델·합격선을 기록한다. 원응답이나 비공개 메모를 공개 로그에 넣지 않는다.

실행 시간 제한은 모델 호출 1회 20초, 형식 복구 포함 메모 1건 총 40초, 호출 횟수 최대 2회다. 20건 전체 최대 호출 수는 40회이며 1차·복구 출력을 분리한다. 시간 초과·거부·인증 실패는 stop으로 종료한다. 실제 모델 실험은 명시적 실행 승인 후 진행한다.

현재 오프라인 러너의 48개 검사는 개발용 구조·분기 검사이며 위 20개 의미 실험 결과를 대체하지 않는다. 18/20과 0/20은 제안값이며 아직 승인된 합격선이 아니다.
