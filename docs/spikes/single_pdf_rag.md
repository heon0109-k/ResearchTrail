# 질문하기: 단일 PDF 검색 범위 변경안

상태: 2026-11-12 사용자 구현 요청에 따른 로컬 실험. 원본 SPEC·온톨로지는 변경하지 않았으며 팀의 제품 명세·수용 기준 승인은 별도다.

SPEC 4.2절의 RAG 질의응답·PDF 자동 추출 제외에 다음 예외를 제안한다: **질문하기에서 열어 둔 PDF 한 편만 기존 PDF.js로 읽고, 브라우저 키워드 검색으로 고른 원문 구절을 기존 Gemini 요청에 제공한다.** 새 키·서버·임베딩 서비스는 추가하지 않는다. 다음 할 일 제안의 입력·호출·저장은 그대로 둔다.

아래는 이번 요청과 SPEC AC6(미확인 정보 보존), AC7(실패 통제), NF3(전송 동의), NF5(검사와 의미 판정 분리)를 근거로 한 추가 검증 **초안**이다. 기존 AC가 RAG를 이미 승인했다는 뜻이 아니며, 새 테스트 통과를 제품 수용 완료로 세지 않는다.

| 사례 | 기대 결과와 이유 |
|---|---|
| R1 전체 검색 | GraphRAG PDF 1쪽에서 `TS와 SS 실험 조건은 각각 어떤 문맥을 사용해?` 검색 시 7쪽 3.3절의 TS·SS 설명을 제공한다. 질문에 쪽 번호는 없다. 사용자 지정 회귀 사례다. |
| R2 쪽 우선 | 질문에 명시한 유효 쪽과 선택 문장의 쪽을 먼저 확보하고, 현재 쪽만 보는 질문은 현재 쪽을 우선한다. |
| R3 전송 예산 | 쪽 후반도 색인하며, 전송 구절 수·문자 수를 제한한다. 원문 텍스트와 쪽 번호를 유지한다. |
| R4 근거 검사 | 보낸 구절에 없는 인용·쪽은 답으로 통과시키지 않고 근거 부족으로 표시한다. 검증된 쪽 링크만 생성한다. 인용 일치는 답변 의미의 정확성을 보증하지 않는다. |
| R5 근거 없는 질문 | 검색 일치 없음과 `found=false`를 각각 확인한다. 유사 키워드가 있어도 질문의 답이 있다는 뜻으로 해석하지 않는다. 실제 모델의 기권은 별도 관찰한다. |
| R6 격리·실패 | 색인은 PDF 문서 객체별 메모리에만 두고 실패를 알린다. PDF 교체·화면 이탈·대화 초기화 후 늦은 검색/응답으로 호출·저장하지 않는다. |
| R7 기존 동작 | 미동의 시 모델 호출 없음. 기존 인용 검사·쪽 링크·다음 할 일 회귀 검사를 유지한다. |

검사 코드: `tests/web_chat_retrieval.test.cjs` (팀 승인 전 초안). 기존 승인 테스트·골든 케이스는 수정하지 않는다. 실제 PDF 검색 결과와 실제 Gemini 응답, 사람이 의미를 판정했는지를 구분해 기록한다.
