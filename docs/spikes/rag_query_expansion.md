# 단일 PDF 검색의 한국어 검색어 확장

2026-11-12 사용자 요청에 따른 기존 RAG 실험 범위의 추가 변경안·검증 초안이다. 원본 SPEC·온톨로지·NextAction 계약은 수정하지 않는다. SPEC AC6/AC7/NF3/NF5의 정보 보존·실패 통제·전송 동의·의미 평가 분리를 적용한다. 팀의 제품 수용 기준 승인은 별도다.

## 방식과 비용

고정 한영 사전은 추가 호출이 없지만 자유로운 한국어 풀어쓰기·논문별 용어를 충분히 다루지 못하고 평가 사례에 맞춘 단어표가 되기 쉽다. 기존 브라우저 키워드 검색을 유지하며, 한국어가 포함된 질문 한 건을 기존 Gemini로 영어 검색어 8–12개로 확장하는 방식을 선택했다. 초기 질문 단독 확장에서는 한국어 목록 반환과, 영어 번역어가 PDF의 실제 표현과 달라 근거를 놓치는 문제가 관찰됐다. 최종 방식은 질문과 현재 PDF에서 동적으로 뽑은 영문 어휘 목록(최대 1,800개·14,000자)을 제공한다. 목록은 빈도·알파벳 순으로 결정하며 문장·쪽 번호를 보존하지 않는다. 정답·원문 구절·정답 쪽·이전 대화는 확장 요청에 넣지 않는다. 구체적인 평가 질문·논문 이름·정답 문구·정답 쪽을 구현 코드에 넣지 않는다.

영어 확장어는 원래 질문에서 얻은 검색어와 합친다. 기존 토큰의 점수 가중치는 1, 추가 토큰은 0.65로 두며 같은 토큰을 중복 계산하지 않는다. 일반적인 영어 어미·하이픈 표기를 검색 키에 정규화한다. 방법 설명에 “요약”이 등장하는 것만으로 서론을 우선하지 않도록 전체 요약 질문의 판별도 좁혔다. 쪽 지정·선택 문장·현재 쪽 우선과 구절 전송 예산은 유지한다. 답변에는 원래 질문과 실제 PDF 구절을 보내며, 생성된 검색어를 근거로 사용하지 않는다. 원문 텍스트와 인용 검사의 정규화 규칙은 바꾸지 않는다.

한국어 질문의 정상 요청은 기존 1회에서 **확장 1회 + 기존 답변 1회 = 2회**가 된다. 기존 답변의 일시 실패 재시도까지 생기면 최대 3회다. 영어로만 된 질문은 확장하지 않는다. 확장은 재시도하지 않고 헤더·본문 수신을 포함해 8초로 제한한다. 실패·형식 오류·빈 검색어이면 원래 질문으로 검색하고 화면에 이를 알린다. 확장에 걸린 시간이 답변 전 대기 시간에 추가된다. 브라우저 타임아웃·중단은 공급자에 이미 접수된 호출의 비용 취소를 보증하지 않는다.

## 검증 초안

새 합성 검사는 `tests/web_chat_query_expansion.test.cjs`에 추가한다. 현재 질문만 1회 전송, 영어 검색어 형식·개수 제한, 원래 검색어 보존, 쪽 우선, 실패·8초 초과 시 재시도 없는 복귀, 늦은 확장의 문서 격리, 원래 질문·원문 인용 검사·확정 작업 보존을 확인한다. 기존 테스트·골든 케이스는 변경하지 않는다.

실제 모델 평가는 `evals/rag_query_expansion_cases.json`의 기존 9문항을 이전과 같은 조건으로 실행한다. 추가 3문항은 구현 전에 PDF 원문에서 정답을 확인했으며 GraphRAG의 청크 길이 상충(3쪽), BERT의 입력 길이 스케줄(13쪽), 기존 평가에 없던 Self-RAG의 지지 상태(4쪽 표 1)를 다룬다. 정답 위치·문구는 평가 파일에만 둔다.

모델·질문·평가 조건을 고정해 한 번씩 제출하고, 실제 확장어·전송 구절·원시 응답·인용 검사·클릭 후 PDF 쪽을 구분해 기록한다. 사람의 의미 판정은 미검증으로 표시하며 이 소수 사례의 관찰을 일반 정확도로 보고하지 않는다. 이전 결과는 `evals/results/rag_query_expansion/20261112-local/before.json`에 보존했다.
