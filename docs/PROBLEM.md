# ResearchTrail 문제 정의서

<a id="problem-statement"></a>
## 1. 한 문장 문제

**과제·프로젝트·스터디·연구를 위해 논문을 읽고 기록하는 학생 중에는 중단한 과업으로 돌아왔을 때 흩어진 기록에서 자료를 남긴 이유·마지막 판단 또는 미해결 질문·다음 작업을 함께 되찾지 못해 이전 대화와 메모를 되짚느라 실제 검토·작성에 착수하는 시간이 늦어지는 사람이 있다.**

이 문제 문장의 직접 근거는 **로그 4의 P04-Q03·Q10·Q11·Q12**와 **로그 6의 P06-Q03·Q10**이다. 다만 두 사람의 과업은 같지 않다. P04는 프로젝트의 출발 방향과 평가 질문 작성, P06은 설명·학습 중심의 발표 준비 사례다. [P04-Q03][I04-03] [P04-Q10][I04-10] [P04-Q11][I04-11] [P04-Q12][I04-12] [P06-Q03][I06-03] [P06-Q10][I06-10]

## 2. 대상과 비대상

### 2.1 1차 사용자 

대상 사용자는 **과제·프로젝트·스터디·연구를 위해 논문을 읽고 기록하며, 중단한 읽기와 탐색을 다시 이어가려는 학생**이다. 전공·학년·논문 분야로 사용 대상을 제한하지 않는다.

검증 참여 조건은 최근 4주 안에 하나의 과업을 위해 논문 두 편 이상을 읽거나 검토하고, 중단 뒤 재개한 경험이 있는 학생이다. 기존 학부생 표본은 현재 확보한 근거 집단이며 모든 학생의 문제·효과를 대표하지 않는다.

대상 여부를 정할 때 “맥락 복원에 실패했는가”를 선별 조건으로 사용하지 않는다. 기존 메모로 수월하게 재개한 사용자도 포함해야 새 제품이 필요한 상황과 필요하지 않은 상황을 구별할 수 있다.

### 2.2 현재 표본의 역할

| 구분 | 참가자 | 근거로 사용하는 범위 |
|---|---|---|
| 문제를 직접 설명하는 중심 사례 | P04 | 자료의 목적, 회의에서 정한 일, 다음 행동을 서로 다른 기록에서 되찾는 과정 |
| 학습 부담과 분리해서 읽어야 하는 지지 사례 | P06 | 저장 이유와 우선 질문의 복원. 이후에도 남는 수식·개념 이해는 별도 문제 |
| 같은 학부생 범위 안의 반례 | P05 | 기존 표의 다음 작업과 링크만으로 수월하게 재개한 과정 |
| 발표 이후 추가 조사 | S01–S03 | 원문 세부 정보 재탐색, 기존 기록을 활용한 재개, 진행 상황 복원을 보여 주는 보완 사례. 기존 3명 판정과 구분 |

## 4. 반증 조건

### 4.1 문제의 실재

**사례 판정 규칙:** 한 참가자의 중심 사건에서 ① 중단 후 재개가 있었고, ② 목적·판단·질문·다음 작업 중 하나 이상을 기존 기록에서 다시 찾는 행동이 있었으며, ③ 그 복원 과정과 실제 과업 시작의 관계가 응답으로 설명되면 지지 사례로 분류한다. 단순한 재독·개념 공부·파일 대기만으로는 지지 사례로 세지 않는다. 같은 사람의 응답 여러 개는 한 명으로 센다.

| 기존 대상 후보 | 잠정 분류 | 판정 근거와 한계 |
|---|---|---|
| P04 | 지지 | 회의 메모를 찾은 후 평가 질문 작성에 착수. 첫 모임의 미결정과 재개 지연은 별개 사건이다. |
| P05 | 해당 중심 사건에서는 비지지 | 정착된 표의 다음 작업과 링크로 재개. 평생 문제가 없었다는 뜻은 아니다. |
| P06 | 넓힌 대상 범위에서 제한적 지지 | 목적·우선 질문 복원이 있었지만, 이후 개념 재학습과 발표 범위 축소의 원인을 전부 같은 문제로 보지 않는다. |

위 분류는 3절 응답에 근거한 잠정 분류이며 최종 검토는 미완료다. 면담일·시각은 인터뷰 메타데이터에 기재돼 있으며 원녹취 대조는 미수행이다. 대상의 기간 조건을 확정할 수 없으면 해당 사례는 “확인 필요”로 남긴다.

**문제 실재의 수치 기준:** 중간발표 9쪽에서 제시한 기준을 유지한다. 기존 학부생 P04·P05·P06 세 명의 최근 재개 사건 중 4.1절의 맥락 복원·착수 지연을 지지하는 사례가 **2명 미만이면 문제 정의를 재검토한다.** 인터뷰를 분석한 뒤 정한 탐색적 기준이며 사전 등록된 가설 검증이나 모집단 비율 추정이 아니다.

**현재 판정:** P06의 제한적 지지를 포함하면 지지 2명으로 재검토 기준에 해당하지 않고, 제외하면 1명으로 해당한다. 따라서 문제 정의를 기각하지 않되, 경계 사례에 의존한 잠정 유지로 본다. 대상 집단 전반의 반복성과 새 도구의 필요성은 확정하지 않는다. P06의 개념 재학습 시간은 제거 가능한 맥락 복원 시간으로 합산하지 않는다.

### 4.2 해결 가설 — 이후 제품 사용으로 판단

**해결 가설 H1:** 사용자가 짧은 기록에 자료의 사용 이유, 실제 판단 또는 미해결 질문, 확인한 다음 작업을 연결해 두고 재개 시 함께 볼 수 있다면, 기존 대화를 넓게 되짚는 부담을 줄이며 필요한 검토·작성에 착수할 수 있다.

이 가설을 구현하는 첫 방법은 **짧은 메모 저장 → 다음 작업 후보 추출 → 사용자 확인 → 과업별 저장 맥락 재열람**이다. AI가 과거의 의도나 새 계획을 만들어 주는 방식은 아니다. 다음 작업 외의 목적·질문·판단·자료 연결은 이번 버전에서 사용자가 입력하거나 선택한다.

**반증이 되는 행동:** 필요한 기록이 정확하게 저장·표시되었는데도, 사용자가 다음 일을 특정하지 못해 이전 대화·메모를 다시 광범위하게 뒤지거나, 추가 기록·수정 부담 때문에 해당 방식을 사용하지 않고 기존 방식으로 돌아가는 경우다.

여기서 연결된 회의 메모나 원문을 열어 실제 검토를 진행하는 행동은 실패가 아니다. “무엇을 하려 했는지 찾으려고 다시 뒤지는 행동”과 “찾은 다음 작업을 수행하려고 자료를 읽는 행동”을 구분한다.


## 5. 추가 조사와 검증 계획 — 2026-11-09 업데이트

[추가 학부생 설문 분석](research/interview.md#additional-survey)에 교수 피드백을 반영한 추가 조사 응답 세 건을 정리했다. S01–S03은 기존 인터뷰에 참여하지 않은 학부연구생 3명이다. 각 후속 답변은 같은 응답자의 구글폼 기록에 연결했다.

[S01 후속](research/interview.md#s01-resume-case)은 원문에서 이미지 크기 조정 방법을 찾으려 한 사례다. [S02 후속](research/interview.md#s02-resume-case)은 PDF의 이전 페이지와 여백 메모를 활용해 수월하게 재개한 사례다. [S03 후속](research/interview.md#s03-q10-f1)은 대화와 엑셀을 다시 보며 진행 상황을 파악하고 다음 할 일을 정한 사례다. [S01-Q10](research/interview.md#s01-q10)에서는 PDF에 남긴 표시와 이전 정리로 읽던 부분부터 이어 봤다. [S02-Q15](research/interview.md#s02-q15)의 수식·그래프 재탐색은 발표 자료에 쓸 원문 위치를 찾는 일이었다. 정리 방식 변경 후의 시간 감소는 응답자의 회상으로 기록한다. 사례별 시간과 활동 범위는 [추가 조사 사례 비교](research/interview.md#supplementary-case-comparison)에 정리했다.

### 5.1 문제 실재 기준과 추가 설문의 관계

문제 실재의 수치 기준은 4.1절의 기존 학부생 3명·지지 2명 미만 재검토 기준을 따른다. 추가 조사에서 S01은 원문 세부 조건 재탐색, S02는 기존 기록으로 재개한 반례, S03은 진행 상황을 되찾고 다음 할 일을 정한 보완 사례로 본다. S03은 실제로 무엇부터 시작했는지 기억하지 못해 착수 지연의 근거로 집계하지 않는다.

추가 응답은 기존 3명 기준의 분모에 합산하지 않는다. 이후 새 조사를 설계할 경우 대상·인원·판정 규칙과 기존 조사와의 관계를 별도로 정한다.

### 5.2 해결 가설의 검증 계획

중간발표에서는 기존 노트 방식과 ResearchTrail의 재개 과정을 비교하겠다고 제시했다. 이번 MVP 체험에서는 참여 가능 인원이 미정인 점과 1주 일정을 고려해 우선 앱 사용 관찰을 진행한다. 기존 방식과 동일 조건의 비교는 후속 검증 과제로 남긴다.

**현재 상태:** 실행 전 계획이며, 참여자 확보와 관찰은 미완료다.

**목표 인원:** 논문 읽기·기록 경험이 있는 학생 3명. 자유 형식 동료평가와 별도로 관찰 참여 동의를 받는다.

**목표 일정:** 11/11~16 기록 단계, 11/12~17 재개 단계 관찰. 두 단계 사이에는 최소 24시간을 둔다. 실행한 결과는 11/18 전 기록하며, 참여자 확보나 일정 조건을 충족하지 못하면 미실행·부분 실행으로 보고한다.

**검증 질문**

1. 사용자가 지시 없이 메모 또는 다음 작업을 남기는가?
2. 남긴 기록으로 중단 전의 의도와 다음 작업을 파악하고 실제 작업을 이어 갈 수 있는가?

#### 체험 절차

1. 기본 조작 방법을 동일하게 안내하고, README의 예시 시나리오 대신 본인의 논문 과업으로 진행한다. 진행자는 특정 메모 내용이나 저장을 지시하지 않는다.
2. README 시나리오를 먼저 따라 해 봤는지 기록한다. 저장 절차를 이미 안내받은 참여자는 자발적 기록 질문에서 판단 불가로 구분하되, 재개 관찰에는 포함할 수 있다.
3. 메모·다음 작업을 스스로 남겼는지, 후보 기능과 직접 입력 중 무엇을 사용했는지, 입력·수정 시간을 기록한다. 미기록 이유는 관찰 후 질문하며 추측하지 않는다.
4. 최소 24시간 뒤 화면 공유로 재개 과정을 관찰한다. 진행자는 조작·내용에 관한 힌트를 주지 않는다.
5. 측정 후 저장된 내용과 실제 의도의 일치 여부, 기록 부담을 질문한다.

#### 측정·판정 규칙

| 항목 | 기준 |
|---|---|
| 시간 시작점 | 앱에서 해당 논문의 저장 기록이 처음 표시된 순간. 재방문 안내 말풍선에 표시된 내용도 포함한다. |
| 시간 끝점 | 필요한 자료의 해당 위치에 도달하고, 확인·읽기·작성 등 다음 작업에 해당하는 행동을 시작한 순간. 화면 행동과 참여자의 설명을 함께 기록한다. |
| 재탐색 | 무엇을 하려 했는지 특정하기 위해 앱 밖의 과거 기록을 열거나, 앱 안에서 다른 논문 기록을 2개 이상 여는 행동 |
| 재탐색 제외 | 이미 특정한 작업을 수행하거나 근거를 확인하기 위해 관련 자료를 여는 행동 |
| 도움 | 진행자가 다음 작업·기록 위치·조작 방법에 관한 힌트를 제공한 경우 |
| 의도 일치 | 중단 전에 하려던 일과 재개한 작업이 맞는지 참여자에게 확인. 이후 목표가 바뀐 경우는 별도 기록 |
| 저장·표시 결함 | 저장 실패·기록 누락·잘못된 작업 표시는 별도 집계하며 성공으로 세지 않음 |
| 완전한 관찰 사례 | 기록 단계와 최소 24시간 뒤 재개 단계를 모두 관찰한 사례. 기록을 남기지 않았어도 두 단계를 관찰했다면 포함 |

재탐색 목적이나 작업 시작 시점이 불명확하면 추측하지 않고 판단 불가로 기록한다.

#### 성공·반증·유보 기준

- **자발적 기록:** 사전 저장 지시의 영향을 받지 않은 참여자 3명 중 2명 이상이 메모 또는 다음 작업을 남기면 잠정 지지한다. 2명 이상이 둘 다 남기지 않으면 재검토한다. 미기록을 곧바로 기록 부담 때문이라고 해석하지 않는다.
- **재개 성공:** 완전한 관찰 사례 3명 중 2명 이상이 기록 내용과 실제 의도가 일치하며, 도움과 재탐색 없이 3분 이내에 작업을 시작한다.
- **재개 반증:** 기록이 정상 표시됐는데도 3명 중 2명 이상이 다음 작업을 특정하지 못해 재탐색하거나, 기록·수정 부담 때문에 사용을 중단하면 해결 방법을 재검토한다.
- **판단 유보:** 각 질문을 판단할 수 있는 사례가 3명 미만이거나 성공·반증 어느 기준에도 해당하지 않으면 그 질문의 결론을 유보한다. 관찰된 미기록·이탈·기술 결함은 별도로 보고한다.

두 질문은 분리해 판정한다. 모든 참여자가 README 저장 안내를 먼저 받았다면 자발적 기록 여부는 유보하고, 재개 여부만 관찰 결과로 판단한다. 재개 성공만으로 자발적 기록까지 지지됐다고 판단하지 않는다.

3명·24시간·3분·2명은 소규모 사용성 관찰을 위한 팀 제안 기준이다. 관찰 시작 전에 확정하며, 도중 변경 시 기존 관찰과 변경 후 관찰을 분리한다. 기존 방식과 같은 조건으로 비교하지 않으므로 시간 단축률·기존 도구 대비 우월성·장기 사용 습관을 주장하지 않는다.
