# ResearchTrail 문제 정의서

<a id="problem-statement"></a>
## 1. 한 문장 문제

**프로젝트나 스터디 발표를 위해 낯선 AI 문헌을 읽는 컴퓨터공학 학부생 중에는 중단한 과업으로 돌아왔을 때 흩어진 기록에서 자료를 남긴 이유·마지막 판단 또는 미해결 질문·다음 작업을 함께 되찾지 못해 이전 대화와 메모를 되짚느라 실제 검토·작성에 착수하는 시간이 늦어지는 사람이 있다.**

이 문제 문장의 직접 근거는 **로그 4의 P04-Q03·Q10·Q11·Q12**와 **로그 6의 P06-Q03·Q10**이다. 다만 두 사람의 과업은 같지 않다. P04는 프로젝트의 출발 방향과 평가 질문 작성, P06은 설명·학습 중심의 발표 준비 사례다. [P04-Q03][I04-03] [P04-Q10][I04-10] [P04-Q11][I04-11] [P04-Q12][I04-12] [P06-Q03][I06-03] [P06-Q10][I06-10]

## 2. 대상과 비대상

### 2.1 1차 사용자 — 범위 제안

최근 4주 안에 하나의 AI 프로젝트 또는 스터디 발표를 위해 논문 두 편 이상을 직접 읽거나 검토하고, 해당 과업을 중단했다가 다시 이어 한 경험이 있는 컴퓨터공학 학부생을 1차 검토 대상으로 삼는다.

대상 여부를 정할 때 “맥락 복원에 실패했는가”를 선별 조건으로 사용하지 않는다. 기존 메모로 수월하게 재개한 사용자도 포함해야 새 제품이 필요한 상황과 필요하지 않은 상황을 구별할 수 있다.

**대상 범위의 변경 제안:** 인터뷰 1.2절과 온톨로지의 `scope.primary_situation`은 “출발 방향을 정하려는 학부생”을 중심 후보로 둔다. 이 초안은 P06의 사례를 함께 검토하기 위해 이를 **“프로젝트·발표 준비 중 문헌 과업을 재개하는 학부생”**으로 조정할 것을 제안한다. 이는 원자료가 이미 확정한 범위가 아니다. 팀이 원래의 좁은 범위를 유지하기로 하면 P06은 인접 사례로 되돌리고, 4.1절의 분모와 판정도 함께 수정한다. [인터뷰 조사 가설](research/interview.md) 및 `ontology.yaml → scope.primary_situation` 참조.

### 2.2 현재 표본의 역할

| 학습 부담과 분리해서 읽어야 하는 지지 사례 | P06 | 저장 이유와 우선 질문의 복원. 이후에도 남는 수식·개념 이해는 별도 문제 |

## 4. 반증 조건

### 4.1 문제의 실재

**사례 판정 규칙 제안:** 한 참가자의 중심 사건에서 ① 중단 후 재개가 있었고, ② 목적·판단·질문·다음 작업 중 하나 이상을 기존 기록에서 다시 찾는 행동이 있었으며, ③ 그 복원 과정과 실제 과업 시작의 관계가 응답으로 설명되면 지지 사례로 분류한다. 단순한 재독·개념 공부·파일 대기만으로는 지지 사례로 세지 않는다. 같은 사람의 응답 여러 개는 한 명으로 센다.

| 기존 대상 후보 | 잠정 분류 | 판정 근거와 한계 |
|---|---|---|
| P04 | 지지 | 회의 메모를 찾은 후 평가 질문 작성에 착수. 첫 모임의 미결정과 재개 지연은 별개 사건이다. |
| P05 | 해당 중심 사건에서는 비지지 | 정착된 표의 다음 작업과 링크로 재개. 평생 문제가 없었다는 뜻은 아니다. |
| P06 | 넓힌 대상 범위에서 제한적 지지 | 목적·우선 질문 복원이 있었지만, 이후 개념 재학습과 발표 범위 축소의 원인을 전부 같은 문제로 보지 않는다. |

위 분류는 3절의 응답을 적용한 **AI의 잠정 분석**이다. P06의 면담일 등 원자료의 미기입 항목을 이 문서에서 새로 채우지 않는다. 대상의 기간 조건을 확정할 수 없으면 해당 사례는 “확인 필요”로 남긴다.

**수치 기준 제안:** 기존 대상 후보 P04–P06 세 명을 같은 규칙으로 재검토했을 때 지지 사례가 두 명 미만이면, 이 초안의 공통 문제 정의를 그대로 채택하지 않고 대상 또는 문제 범위를 다시 작성한다. 대상 적격성이나 사건 판정 자체가 불분명하면 기각으로 단정하지 않고 판단을 보류한다.

**현재의 잠정 해석:** 넓힌 범위를 전제로 하면 지지 두 명, 중심 사건 비지지 한 명이다. 그러나 이 수치 기준은 인터뷰를 읽은 뒤 제안한 **사후 검토 기준**이다. 사전 등록된 가설 검증에 통과했다거나, 학부생의 2/3가 이 문제를 겪는다고 주장하지 않는다. 원래의 “출발 방향 선정”만 유지할 경우 이 집계를 그대로 쓰지 않는다.

### 4.2 해결 가설 — 이후 제품 사용으로 판단

**해결 가설 H1:** 사용자가 짧은 기록에 자료의 사용 이유, 실제 판단 또는 미해결 질문, 확인한 다음 작업을 연결해 두고 재개 시 함께 볼 수 있다면, 기존 대화를 넓게 되짚는 부담을 줄이며 필요한 검토·작성에 착수할 수 있다.

이 가설을 구현하는 첫 방법은 **짧은 메모 저장 → 다음 작업 후보 추출 → 사용자 확인 → 과업별 저장 맥락 재열람**이다. AI가 과거의 의도나 새 계획을 만들어 주는 방식은 아니다. 다음 작업 외의 목적·질문·판단·자료 연결은 이번 버전에서 사용자가 입력하거나 선택한다.

**반증이 되는 행동:** 필요한 기록이 정확하게 저장·표시되었는데도, 사용자가 다음 일을 특정하지 못해 이전 대화·메모를 다시 광범위하게 뒤지거나, 추가 기록·수정 부담 때문에 해당 방식을 사용하지 않고 기존 방식으로 돌아가는 경우다.

여기서 연결된 회의 메모나 원문을 열어 실제 검토를 진행하는 행동은 실패가 아니다. “무엇을 하려 했는지 찾으려고 다시 뒤지는 행동”과 “찾은 다음 작업을 수행하려고 자료를 읽는 행동”을 구분한다.
