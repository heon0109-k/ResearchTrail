## 2. 이번 위임 범위와 실행

강의07 지침을 읽고 evals 설계·20건 입력 초안·미확정 사람 결정 파일·오프라인 실행기·현재 stub 어댑터를 준비한다. 기존 골든 케이스, 테스트 기대값, SPEC·온톨로지·모델 프롬프트·스키마와 앱 구현은 이번 작업에서 변경하지 않는다. 기존의 별도 로컬 변경은 유지한다.

실제 모델/외부 호출, 커밋·푸시, 승인자·승인일시·사람 라벨 대필, 합격선 확정, 평가 결과에 맞춘 정답 수정은 위임 범위가 아니다. 설계·입력은 AI 초안이며 절대 규칙 기대값은 null로 남긴다. 범위 충돌·미명세 판정이 필요하면 공식 평가 실행을 차단하고 미확정 항목을 보고한다.

## 3. 기계 검증 루프

- 구조 검사: --check로 20건·범주·중복 ID·지원 채점기·기대 조건 형식을 검사한다. 제품을 실행하지 않는다.
- self-test: 평가 입력 대신 별도 임시 합성 자료로 정상 채점, 오답·형식 오류·미지원 키·누락 출력·분모 유지, 미승인 실행 차단, 결과/이력 저장을 확인한다.
- 실제 실행 로그와 통과 근거는 evals/RUNNER_CHECK.md를 확인한다. self-test 기준은 러너 구현 검증용이며 사람의 제품 기대값이나 골든 기준을 대체하지 않는다.
